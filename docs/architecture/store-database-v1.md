# مدل دیتابیس فروشگاه تایر – فاز اول

فروشگاه پایگاه داده‌ی مستقل خود را دارد و به جداول ERP وابسته نیست. پیاده‌سازی محلی فعلی SQLite و EF Core است؛ فایل پیش‌فرض در `tire-store-api/src/TireStore.Api/App_Data/tire-store.db` قرار می‌گیرد.

## مدل رابطه‌ای

```text
Stores 1 ─── * StoreInventory * ─── 1 Products
```

### `Stores`

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `Id` | integer PK | شناسه فروشگاه |
| `Name` | varchar(160) | نام فروشگاه |
| `Address` | varchar(300) | نشانی |

### `Products`

| فیلدها | توضیح |
| --- | --- |
| `Id`, `CreatedAt` | کلید و زمان ایجاد |
| `Brand`, `Model`, `Size` | مشخصات پایه‌ی محصول |
| `Width`, `Profile`, `Rim`, `Pattern`, `LoadIndex`, `Noise`, `Year`, `Country` | جزئیات فنی مطابق فرم پنل |
| `Warranty`, `WarrantyMonths`, `Description`, `Images` | گارانتی، توضیحات و تصاویر؛ تصاویر به صورت JSON ذخیره می‌شوند |

روی ترکیب برند، مدل و سایز ایندکس وجود دارد.

### `StoreInventory`

| فیلد | نوع | توضیح |
| --- | --- | --- |
| `StoreId` | integer PK/FK | فروشگاه |
| `ProductId` | integer PK/FK | محصول |
| `Quantity` | integer | تعداد موجودی در همان فروشگاه |
| `Price` | decimal | قیمت جفت به تومان در همان فروشگاه |

کلید اصلی مرکب `(StoreId, ProductId)` است. بنابراین مشخصات فنی در `Products` مشترک است و قیمت/موجودی هر فروشنده در `StoreInventory` نگهداری می‌شود. حذف محصول، رکوردهای موجودی آن را نیز حذف می‌کند.

## اتصال پنل و اپ

- پنل فعلی از مسیرهای `/api/admin/products` استفاده می‌کند و محصول/قیمت/موجودی را برای فروشگاه پیش‌فرض با شناسه ۱ ثبت می‌کند.
- اپ مسیر `/api/store/products?shopId={id}` را می‌خواند؛ API قیمت و موجودی همان فروشگاه را در DTO محصول قرار می‌دهد.
- تغییر موجودی در سفارش به‌صورت تراکنشی روی موجودی همان فروشگاه انجام می‌شود و رد سفارش آن را برمی‌گرداند.
- اپ هر ۱۵ ثانیه فهرست فروشگاه انتخاب‌شده را تازه می‌کند.

## محدوده‌ی پیاده‌سازی فعلی

محصول، فروشگاه و موجودی اکنون پایدار و دیتابیس‌محور هستند. اعتبار، سفارش و اقساط فعلاً در حافظه‌اند و در گام بعد باید جداول مستقل و تراکنش مشترک برای سفارش/رزرو اعتبار ایجاد شود. احراز هویت و RBAC پنل هم هنوز برای انتشار واقعی لازم است. قبل از استفاده‌ی production باید `EnsureCreated` با migrationهای نسخه‌بندی‌شده جایگزین شود و مسیر/پشتیبان‌گیری دیتابیس براساس محیط استقرار تنظیم شود.
